# 테스트

## 자동 검사

```bash
bunx tsc -p tsconfig.json --noEmit
bunx tsc -p tsconfig.worker.json --noEmit
bunx vite build
```

백엔드 스모크(Worker가 8787에서 실행 중이어야 함):

```bash
./.tools/node/node.exe .tools/smoke.mjs
```

스모크가 확인하는 것:

- 비밀번호 입장/오답 거부/세션, 수업 생성, 학생 입장·재입장
- 집중 이벤트 기록·중복 억제
- 선생님 WebSocket 스냅샷
- 보드 공유 → 학생 수신 → 학생 카드 → 선생님 보드 반영
- 콘솔 종료 시 학생에게 `board: null` 전달
- PDF 메타데이터만 공유 → 학생 요청 → 선생님에게 요청 전달 → 조각 중계
- WebRTC 시그널링(요청/중지) 중계
- 학습지 제출 답변을 선생님 스냅샷에서 확인
- 입력 관찰 켜기/끄기, 학생 활동 입력이 교사에게 전달되고 끄면 중단
- 스펠링 정답 정규화·채점·마감 후 정답 공개, OX 선택지·채점
- 수업 종료 후 신규 참가 409
- 수업 종료 즉시 참가자·스냅샷·답변·입력 미리보기 삭제
- API에 녹화/R2 관련 필드가 없음

## 수동 확인 (두 기기 권장)

1. 교사 PC에서 `/login` 비밀번호 입장 → 활동 보드에서 템플릿 보드 생성.
2. 수업 생성 → 콘솔 열기.
3. 학생 기기에서 참가 코드 입력 → 이름만으로 입장(전체화면·화면 공유 선택).
4. 콘솔 **활동 보드**에서 보드 열기 → 학생 화면에 카드/안내 표시, 학생 카드가 교사 화면에 표시.
5. **수업 도구**에서 PDF 선택 → 배포 → 학생이 “학습지 PDF 받기” → 미리보기/저장 → 답 작성 → 제출.
6. **게임**에서 영단어 스펠링 세트를 시작 → 학생이 입력 → 교사 화면 채점 → 응답 마감 후 정답 공개.
7. **패들렛**에 일반 `padlet.com` 주소 또는 embed 코드를 붙여 넣어 embed 주소가 자동으로 잡히고 앱 안에서 표시되는지 확인(막히면 새 창).
8. **입력 관찰**을 켜고 학생 화면의 고지와 교사 화면의 입력 미리보기를 확인한 뒤 끄기.
9. **화면 공유**에서 선생님 화면 공유 → 학생 화면에 영상 표시.
10. 학생 카드에서 **화면 요청** → 학생이 허용 → 교사 화면에 학생 화면 표시.
11. 콘솔 탭을 닫고 학생 화면에서 보드가 사라지고 PDF를 더 받을 수 없는지 확인.
12. **수업 종료** 후 참가자 0명, 콘솔 내용이 비워졌는지 확인.

## 이 환경에서 확인한 범위

- 위 자동 검사와 스모크는 로컬 Miniflare에서 통과했습니다.
- 브라우저에서는 비밀번호 입장, 대시보드, 게임·패들렛 탭, 입력 관찰 토글, 학생 입장 화면이 렌더링되는지 확인했습니다.
- 실제 화면 선택 창과 WebRTC 영상 연결, 실제 Padlet 보드 임베드, 실제 PDF 재조립·모바일 미리보기,
  Android/iOS 실기기, 다른 네트워크/TURN 환경은 이 컴퓨터에서 검증하지 못했습니다.
